# Windows Security Logs Analysis

**Domain:** Cybersecurity | Security Operations Center (SOC)  
**Lab Type:** Hands-on Practical  
**Platform:** Windows 10/11 or Windows Server  
**Focus:** Authentication Monitoring, Failed Logins, and Security Event Investigation

---

## 🎯 Objective

Understand Windows Security Logs and learn how to investigate successful logins, failed authentication attempts, account lockouts, and security group membership changes using Windows Event Viewer.

## 1. What Are Windows Security Logs?

Windows Security Logs record security-related events generated by the operating system. These logs help SOC analysts monitor authentication activity, investigate suspicious behavior, and identify potential security incidents.

### Common Security Events

- Successful and failed login attempts
- Account lockouts
- User account creation and deletion
- Security group membership changes
- Special privileges assigned to a logon
- Changes to audit policies

**Log Location:** `Event Viewer → Windows Logs → Security`

---

## 2. Important Windows Security Event IDs

| Event ID | Description | Security Relevance |
|---|---|---|
| 4624 | Successful logon | Identify successful account access |
| 4625 | Failed logon | Investigate unsuccessful authentication |
| 4634 | Account logged off | Review session termination |
| 4648 | Logon attempted using explicit credentials | Investigate unusual credential use |
| 4672 | Special privileges assigned to a new logon | Review privileged sessions |
| 4720 | User account created | Detect unexpected account creation |
| 4726 | User account deleted | Investigate account removal |
| 4732 | Member added to a security-enabled local group | Detect unexpected privilege changes |
| 4740 | User account locked out | Investigate repeated failed authentication |

*Note: These events depend on the relevant Windows auditing configuration and the type of activity performed.*

# 3. Practical Lab — Detecting Failed Login Attempts

## Lab Requirements

- Windows 10/11 or compatible Windows Server
- Windows Event Viewer
- PowerShell or Command Prompt
- Administrative privileges where required

## Step 1 — Create a Test User

Open PowerShell as Administrator and execute:

```powershell
$Password = Read-Host "Enter a test password" -AsSecureString
New-LocalUser -Name "haxuser1" -Password $Password
```

Use a unique test password. Do not use your personal or production account credentials.

If the account already exists, use a different test username.

## Step 2 — Generate a Failed Authentication Attempt

Open Command Prompt or PowerShell and run:

```cmd
net use \\127.0.0.1\IPC$ /user:haxuser1 WrongPassword
```

This attempts to authenticate to the local computer using an intentionally incorrect password.

### Command Breakdown

| Component | Explanation |
|---|---|
| `net use` | Connects to or manages network connections |
| `\\127.0.0.1\IPC$` | Targets the local computer's IPC administrative share |
| `/user:haxuser1` | Specifies the account used for authentication |
| `WrongPassword` | Supplies an intentionally incorrect password |

**Expected Result:** Authentication should fail if the supplied credentials are invalid. The exact error and event generated depend on the system configuration.

## Step 3 — Locate Event ID 4625

1. Press `Win + R`.
2. Enter `eventvwr.msc`.
3. Navigate to:

   `Windows Logs → Security`

4. Click **Filter Current Log**.
5. Enter `4625` in the Event IDs field.
6. Apply the filter.
7. Inspect events recorded around the time of the test.

### Fields to Investigate

| Field | Purpose |
|---|---|
| Time Created | Establish when the failure occurred |
| Account Name | Identify the account involved |
| Logon Type | Understand the type of logon attempted |
| Workstation Name | Identify the originating workstation, if available |
| Source Network Address | Identify the source IP address, if available |
| Status / Sub Status | Understand the authentication failure reason |

**Important:** Because this test targets `127.0.0.1`, the source address may be loopback, blank, or represented differently. Do not assume every field will contain a value.

## Step 4 — Analyze the Event

Answer the following questions:

1. Which account was involved in the failed authentication?
2. When did the event occur?
3. What was the logon type?
4. What status or substatus was recorded?
5. Is the activity consistent with the test you performed?
6. What additional events would you investigate if repeated failures occurred?

### SOC Investigation Insight

A single failed login is not enough to confirm an attack. Multiple failures involving the same account, several accounts, or unusual source addresses may warrant further investigation.

Correlate Event ID 4625 with successful logons, account lockouts, and other available security events to establish context.

# 4. Investigating Successful Logons — Event ID 4624

1. Return to `Windows Logs → Security`.
2. Select **Filter Current Log**.
3. Enter Event ID `4624`.
4. Inspect events recorded around your test period.
5. Review the account name, timestamp, logon type, and source information where available.

**Purpose:** Understand how Windows records successful authentication and learn to distinguish successful access from failed authentication.

*Do not assume a 4624 event was generated by the test user. Verify the account name and timestamp before using an event as evidence.*

## 6. Conclusion

This lab demonstrates how Windows Security Logs can be used to investigate authentication activity.

Key skills practiced:

- Locating Windows Security Logs
- Filtering events by Event ID
- Analyzing successful and failed logons
- Interpreting account and logon details
- Collecting evidence for a SOC investigation
