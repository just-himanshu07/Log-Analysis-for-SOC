# Network-Based Attack Detection Using UFW

**Domain:** Cybersecurity | Security Operations Center (SOC)  
**Lab Type:** Hands-on Practical  
**Platform:** Kali Linux and Ubuntu Linux  
**Focus:** Port Scan Detection, Firewall Logging, and Network Traffic Analysis

---

## 🎯 Objective

Simulate a TCP port scan in an authorized lab environment and investigate firewall logs on Ubuntu using UFW. Learn how to identify blocked traffic, analyze source IP addresses and destination ports, and recognize potential network reconnaissance.

## 1. What Is a Network Port Scan?

A **port scan** is a technique used to identify accessible ports and potentially running services on a host.

Tools such as Nmap help security professionals discover network services and assess a system's exposed attack surface.

### Why Port Scanning Matters

- Identifies potentially exposed network services.
- Helps security teams assess firewall configurations.
- May indicate reconnaissance before an attempted attack.
- Supports network inventory and authorized security testing.

**Important:** Port scanning is not inherently malicious. SOC analysts must evaluate the source, frequency, target, and surrounding activity before classifying it as suspicious.

---

## 2. Understanding Nmap

Nmap (Network Mapper) is an open-source tool used for network discovery and security auditing.

### Common Scan Types

| Scan Type | Option | Purpose |
|---|---|---|
| TCP SYN Scan | `-sS` | Performs TCP SYN-based port scanning |
| TCP Connect Scan | `-sT` | Uses the operating system's TCP connect function |
| UDP Scan | `-sU` | Investigates UDP ports |
| Ping Scan | `-sn` | Discovers hosts without performing a port scan |

---

## 3. Understanding UFW

**UFW (Uncomplicated Firewall)** is a firewall management tool commonly used on Ubuntu and other Linux distributions. It provides a simplified interface for managing firewall rules.

### Useful Commands

| Command | Purpose |
|---|---|
| `sudo ufw status` | Displays firewall status and rules |
| `sudo ufw status numbered` | Displays numbered firewall rules |
| `sudo ufw enable` | Enables the firewall |
| `sudo ufw logging on` | Enables firewall logging |
| `sudo ufw logging high` | Enables more detailed logging |
| `sudo ufw reload` | Reloads firewall rules |

### UFW Log Location

```text
/var/log/ufw.log
```

On systems using different logging configurations, UFW messages may instead be available through the system journal or another configured logging destination.

# 4. Practical Lab — Detecting a Port Scan

## Lab Setup

| Machine | Role | Tool |
|---|---|---|
| Kali Linux | Scanner | Nmap |
| Ubuntu Linux | Target | UFW Firewall |

**Prerequisites:** Both machines must have network connectivity, and you must have authorization to scan the target. Use your actual lab IP addresses rather than the example addresses in this document.

## Step 1 — Identify the Target IP

On Ubuntu, run:

```bash
ip addr
```

Record the IP address of the interface connected to your lab network.

On Kali, verify connectivity to the target:

```bash
ping -c 4 TARGET-IP
```

Replace `TARGET-IP` with the Ubuntu machine's actual IP address. A failed ping does not necessarily mean the host is unreachable because ICMP traffic may be filtered.

## Step 2 — Install and Configure UFW

On Ubuntu, execute:

```bash
sudo apt update
sudo apt install ufw
sudo ufw status verbose
```

If UFW is inactive, enable it after checking the existing rules and ensuring you will not lose remote access.

```bash
sudo ufw logging on
sudo ufw logging high
```

**Warning:** Enabling or changing firewall rules over SSH can interrupt your connection. Confirm that your access is permitted before applying changes.

## Step 3 — Block HTTP Traffic From the Kali Machine

On Ubuntu, add a rule using the actual Kali IP address:

```bash
sudo ufw deny from KALI-IP to any port 80 proto tcp
```

Replace `KALI-IP` with the Kali machine's real IP address.

Verify the rule:

```bash
sudo ufw status numbered
```

This rule blocks matching TCP traffic to destination port 80 from the specified source address.

## Step 4 — Simulate a TCP Port Scan

On Kali, run the following against your authorized Ubuntu target:

```bash
nmap -sT -p 80 TARGET-IP
```

This performs a TCP connect scan of port 80.

**Expected Result:** If the firewall rule is active and traffic matches it, Nmap may report the port as `filtered` or otherwise indicate that the connection was blocked. Results depend on the network and firewall configuration.

*Note: A single-port scan is a basic detection exercise. It does not demonstrate detection of a broad multi-port scan.*

## Step 5 — Monitor UFW Logs

On Ubuntu, inspect recent firewall log entries:

```bash
sudo tail -n 50 /var/log/ufw.log
```

To monitor new log entries:

```bash
sudo tail -f /var/log/ufw.log
```

To filter entries for the Kali machine, open a separate terminal and run:

```bash
sudo grep "SRC=KALI-IP" /var/log/ufw.log
```

Replace `KALI-IP` with the actual source IP address.

To focus on blocked traffic:

```bash
sudo grep "SRC=KALI-IP" /var/log/ufw.log | grep "\[UFW BLOCK\]"
```

If `/var/log/ufw.log` does not exist or contains no matching entries, check the system journal:

```bash
sudo journalctl -k --since "10 minutes ago"
```

Review the firewall logging configuration and generate the test traffic again if necessary.

## 5. Analyzing UFW Log Entries

### Example Log

```text
Oct 18 14:32:10 ubuntu kernel: [UFW BLOCK] IN=ens33 OUT= MAC=... SRC=192.168.1.50 DST=192.168.1.100 LEN=60 PROTO=TCP SPT=54321 DPT=80 SYN
```

*This is an illustrative example, not evidence collected from a real lab.*

### Log Breakdown

| Field | Meaning |
|---|---|
| Timestamp | When the event was recorded |
| `UFW BLOCK` | Traffic blocked by UFW |
| `IN` | Incoming network interface |
| `SRC` | Source IP address |
| `DST` | Destination IP address |
| `PROTO` | Network protocol |
| `SPT` | Source port |
| `DPT` | Destination port |
| `SYN` | TCP SYN flag |

### SOC Investigation Questions

1. Which source IP generated the traffic?
2. Which destination IP and port were targeted?
3. Was the traffic blocked?
4. Are there repeated connection attempts from the same source?
5. Does the source contact multiple ports or hosts?
6. Do other logs indicate additional suspicious activity?

---

## 6. Detection and Response

When investigating potential port scanning, a SOC analyst should:

- Review repeated blocked connection attempts.
- Identify the source and destination IP addresses.
- Examine the destination ports and protocols.
- Correlate firewall records with network and endpoint telemetry.
- Validate whether the activity matches authorized testing.
- Escalate or block traffic according to the organization's incident response procedures.

**Investigation Tip:** A firewall block log demonstrates that matching traffic was blocked; it does not, by itself, prove that a complete port scan occurred.
