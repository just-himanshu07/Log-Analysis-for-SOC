# Linux Auth Log Analysis

## 🎯 Objective
Learn how to check Linux login logs and identify repeated failed SSH login attempts that may indicate a brute-force attack.

## 1. What Are Linux Authentication Logs?

Authentication logs record login activities on a Linux system. They help us identify successful logins, failed logins, and suspicious access attempts.

**Common log files:**
- `/var/log/auth.log` — Ubuntu and Debian
- `/var/log/secure` — Many CentOS and RHEL systems

## 2. What Is an SSH Brute-Force Attack?

An SSH brute-force attack happens when someone repeatedly tries different passwords to access a system.

**Common signs:**
- Many failed login attempts.
- Repeated attempts from the same IP address.
- Attempts using different usernames.
- A successful login after many failed attempts.

- Kali Linux

## 4. Practical Lab — Detect Failed SSH Logins

### Step 1: Check the SSH Service

On Ubuntu, run:

```bash
sudo systemctl status ssh
```

If SSH is not installed, run:

```bash
sudo apt update
sudo apt install openssh-server
sudo systemctl enable --now ssh
```

### Step 2: Generate Failed Login Attempts

Use a test account on your own lab machine. Try logging in with an incorrect password a few times.

Do not test systems without permission.

### Step 3: Check Failed Login Logs

Run this command on Ubuntu:

```bash
sudo grep "Failed password" /var/log/auth.log
```

It displays log entries for failed password attempts.

### Step 4: Watch Logs in Real Time

Run:

```bash
sudo tail -f /var/log/auth.log
```

New log entries will appear as they are recorded. Press `Ctrl + C` to stop.

### Step 5: Understand the Log

Example:

```text
Oct 18 14:30:12 ubuntu sshd[1234]: Failed password for invalid user testuser from 192.168.1.50 port 54321 ssh2
```

**Explanation:**
- `Oct 18 14:30:12` — Date and time
- `ubuntu` — Computer name
- `sshd` — SSH service
- `testuser` — Username used
- `192.168.1.50` — Source IP address
- `Failed password` — Login failed

*This is an example log, not a real lab result.*

## 5. What Should a SOC Analyst Check?

- Which IP address is making login attempts?
- Which username is being targeted?
- How many login attempts failed?
- Did a successful login happen after the failures?
- Is the activity normal or suspicious?

Many failed logins may indicate a brute-force attack, but further investigation is needed before confirming it.

## 6. How to Protect the System

- Use strong passwords.
- Use SSH keys where possible.
- Allow SSH access only from trusted sources.
- Monitor authentication logs regularly.
- Use tools such as Fail2ban to limit repeated failed attempts.

## 7. Conclusion

In this lab, we learned how to check Linux authentication logs and identify repeated failed SSH login attempts.

These skills help SOC analysts investigate suspicious login activity and detect possible brute-force attacks.
