# Windows PowerShell Logs Analysis

**Domain:** Cybersecurity | Security Operations Center (SOC)  
**Lab Type:** Hands-on Practical  
**Platform:** Windows 10/11 or Windows Server  
**Focus:** PowerShell Logging, Event Investigation, and Threat Detection

---

## 🎯 Objective

Understand Windows PowerShell logging, identify important PowerShell event IDs, and investigate command execution using Windows Event Viewer to recognize potentially suspicious activity.


## 1. What Are Windows PowerShell Logs?

Windows PowerShell logs record information about PowerShell activity, depending on the logging policies and configuration enabled on the system.

SOC analysts use these logs to investigate command execution, script activity, administrative operations, and potentially malicious behavior.

### Important PowerShell Event IDs

| Event ID | Description |
|---|---|
| 4103 | Module logging: records pipeline execution details when configured |
| 4104 | Script Block Logging: records script block content |
| 4105 | Script block execution started, when invocation logging is enabled |
| 4106 | Script block execution completed, when invocation logging is enabled |

**Important:** Event ID 4101 is not the standard PowerShell command execution event described in the original lab. Event ID 4698 is associated with scheduled task creation, not PowerShell Module Logging.

## 3. Preparation — Enable PowerShell Logging

1. Press `Win + R`.
2. Enter `gpedit.msc`.
3. Navigate to:

   `Computer Configuration → Administrative Templates → Windows Components → Windows PowerShell`

4. Enable **Turn on PowerShell Script Block Logging**.
5. Optionally enable **Turn on PowerShell Module Logging** and configure the required modules.
6. Apply the settings.

*Note: Script Block Logging is required for Event ID 4104. Module Logging is a separate policy used for Event ID 4103. Script Execution policy controls script execution behavior and is not the same as either logging policy.*

# 4. Practical Lab — Generate and Investigate PowerShell Events

## Step 1 — Generate PowerShell Activity

Open PowerShell and execute:

```powershell
Start-Process "notepad.exe" -ArgumentList "C:\Windows\System32\drivers\etc\hosts"
```

### Expected Behavior

- Launches Notepad.
- Opens the Windows `hosts` file.
- Generates PowerShell activity that can be investigated in the relevant logs.

This is a benign administrative test. Opening the file does not modify it unless you explicitly save changes.

## Step 2 — Locate PowerShell Events

1. Press `Win + R`.
2. Enter `eventvwr.msc`.
3. Navigate to:

   `Applications and Services Logs → Microsoft → Windows → PowerShell → Operational`

4. Select **Filter Current Log**.
5. Enter Event ID `4104`.
6. Inspect events recorded around the time you ran the command.

If you enabled Module Logging, also filter for Event ID `4103`.

**Note:** Neither event is guaranteed to contain the entire command in every configuration. Verify that logging is enabled and inspect the actual event details.

## Step 3 — Analyze the Event

Record the following information where available:

| Field | Investigation Purpose |
|---|---|
| Event ID | Identifies the type of event |
| Time Created | Establishes when the activity occurred |
| User / Execution Context | Helps identify the account involved |
| Script Block Text | Shows recorded script content in Event ID 4104 |
| Command Details | Helps explain the activity |
| Related Process Activity | Provides additional context when correlated with other logs |

### Investigation Questions

1. What PowerShell activity was recorded?
2. When did the activity occur?
3. Which command or script block was logged?
4. Is the activity consistent with the test performed?
5. What additional logs could help investigate suspicious PowerShell behavior?

## 5. Why PowerShell Logging Matters for Blue Teams

Attackers sometimes abuse legitimate Windows utilities and scripting tools to execute commands, download files, establish persistence, or perform reconnaissance.

### Examples of LOLBAS Tools

LOLBAS stands for **Living Off The Land Binaries, Scripts and Libraries**.

| Tool | Potential Abuse |
|---|---|
| `powershell.exe` | Execute scripts and perform system reconnaissance |
| `certutil.exe` | Download or decode files |
| `mshta.exe` | Execute HTML applications or script-based content |
| `regsvr32.exe` | Load DLLs and execute associated code |
| `rundll32.exe` | Execute exported DLL functions |
| `bitsadmin.exe` | Transfer files using BITS |
| `msbuild.exe` | Execute code through build processes |
| `schtasks.exe` | Create or modify scheduled tasks |

Reference: [LOLBAS Project](https://lolbas-project.github.io/)

**SOC Investigation Tip:** The presence of one of these tools does not automatically indicate malicious activity. Investigate the command line, parent process, user, execution time, network connections, and surrounding events.
